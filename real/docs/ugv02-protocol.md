## 1 链路

- 串口 115200 8N1（`General_Driver.ino`：`Serial.begin(115200)`）。
- 一条指令 = 一行 JSON，以 `\n` 结尾；固件按行解析，解析失败的行静默丢弃、无错误回包（`uart_ctrl.h::serialCtrl`）。
- 回显：`uartCmdEcho` 缺省为 1，固件会把收到的指令原样回写。关闭用 `{"T":143,"cmd":0}`。驱动层读回包时须能跳过回显行。

## 2 指令

| 指令 | JSON | 说明 |
|---|---|---|
| 左右轮速度 | `{"T":1,"L":0.2,"R":0.2}` | `L`、`R` 须为浮点；超出 ±2.0 的值被固件直接忽略（不限幅、不回包）。刷新心跳 |
| 线速度＋角速度 | `{"T":13,"X":0.1,"Z":0.3}` | m/s、rad/s；固件换算 `L = X − Z·W/2`、`R = X + Z·W/2`，`W` 为轮距。源码注明不适用于无编码器的型号。刷新心跳 |
| PWM 直驱 | `{"T":11,"L":164,"R":164}` | ±255，开环。**本卡不用** |
| 查询一次底盘反馈 | `{"T":130}` | 回一条 `T=1001`，见 §3 |
| 连续反馈开关 | `{"T":131,"cmd":1}`／`{"T":131,"cmd":0}` | 缺省关 |
| 连续反馈附加间隔 | `{"T":142,"cmd":<ms>}` | 源码标注 dev |
| 心跳超时设置 | `{"T":136,"cmd":3000}` | 单位 ms，缺省 3000 |
| 回显开关 | `{"T":143,"cmd":0}` | 见 §1 |
| 型号设置 | `{"T":900,"main":2,"module":0}` | 见 §5 到货核对 |

## 3 反馈 `T=1001`

字段（`ugv_advance.h::baseInfoFeedback`）：`L`、`R` 左右轮速度（编码器测得）；`r`、`p`、`y` 横滚／俯仰／航向；`temp`；`v` 电压。

**该版本固件不回累计里程，只回轮速。** 里程由驱动层在上位机侧对 `L`、`R` 按采样间隔积分得到。若到货固件另有累计里程字段，到货后再改。

## 4 心跳与停车

- 固件记录最近一次运动指令（`T=1`、`T=11`、`T=13`）的到达时刻；超过心跳超时未再收到运动指令，固件把目标速度置 0（`movtion_module.h::heartBeatCtrl`）。查询类指令不刷新心跳。
- **固件里没有找到专用的底盘急停指令。** 仓内 `harness/robot_real.py` 与 `protocol/kit-candidates.md` 写的 `{"T":0}` 出自另一个仓库（`ugv_rpi`），在本固件源码的指令分发里没有对应分支。
- 因此驱动层的急停 = 立即发 `{"T":1,"L":0.0,"R":0.0}` ＋ 上位机侧锁存（锁存期间拒发任何非零速度）＋ 停止续发心跳，让固件超时自停兜底。`{"T":0}` 不作为唯一手段。

## 6 给 mock 串口的最低行为要求

mock 须复现：按行收 JSON；坏行静默丢弃；回显缺省开、可关；`T=1`／`T=13` 刷新心跳并设定目标速度；超过心跳超时目标速度归零；超出 ±2.0 的 `T=1` 被忽略；`T=130` 回一条 `T=1001`，`L`、`R` 等于当前目标速度；时间由测试注入，不读墙钟。
