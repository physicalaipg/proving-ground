# yb-eet01-json：板卡厂商 YB-EET01 V2.0 板的 JSON 串口固件

> 内部工单（裁定 2026-09-28-05）。编写：维护者，2026-09-28。**已编译通过，未烧录，未经实机核对。**
> 烧录前必须先按 `docs/backup-restore.md` 做整片备份，两次读出哈希一致才算成立；不成立不烧录。

让旧车（板卡厂商麦轮车，YB-EET01 V2.0 板＋四只 310 编码电机）说 UGV02 的串口 JSON 指令子集，`real/` 驱动层不改。麦轮按四轮差速运行，协议真机段标「非参考平台」。

## 指令

115200 8N1，一行一条 JSON，`\n` 结尾。协议细节与 UGV02 的出入见 `real/docs/ugv02-protocol.md` §8。

| 指令 | 行为 |
|---|---|
| `{"T":1,"L":0.2,"R":0.2}` | 左右轮目标速度，m/s。任一值超 ±2.0 整条忽略、不回包；超固件限幅（缺省 ±0.5）夹到限幅值。刷新心跳 |
| `{"T":130}` | 回一条 `{"T":1001,"L":…,"R":…,"r":…,"p":…,"y":…,"temp":…,"v":…,"low_voltage":0,"reset_reason":1,"boot":…,"tl":…,"tr":…}`。前八个字段的名与次序同 UGV02；`low_voltage`、`reset_reason`、`boot`、`tl`、`tr` 是新增字段，排在最后。`tl`、`tr` 是控制侧当前目标轮速（审查 X3-08）：零速已收下、停车序号先到的保持态、各种锁存时都是 0。`L`、`R`、`v`、`low_voltage`、`tl`、`tr` 取控制环上一拍的快照，至多旧 10 ms |
| `{"T":136,"cmd":3000}` | 心跳超时，毫秒。夹在 100～3000 之间，不能关掉也不能放长 |
| `{"T":143,"cmd":0}` | 回显开关。缺省关 |
| 其余 `T` | 回 `{"T":-1,"err":"unknown_cmd","got":<T>}` |
| 参数缺失或类型不对 | 回 `{"T":-1,"err":"bad_args","got":<T>}` |
| 不是一层 JSON 对象的行 | 静默丢弃 |

开机打印一行标识：`{"fw":"yb-eet01-json","ver":"0.2.0","proto":"ugv02-subset-1","board":"YB-EET01","imu":1}`。`imu` 为 0 表示 IMU 没认到，姿态与温度报 0，运动控制不受影响。

## 安全行为

- **停车锁存**：心跳超时、低压、复位共用一个状态量，锁存期间目标速度恒为 0。三者只差清除规则，对照表在 `real/README.md`。
- **心跳锁存**：超过心跳超时没有收到有效的 `T:1` 即锁存并刹停；下一条有效 `T:1` 清除，与 UGV02 相同。检查放在 10 ms 控制环里。查询类指令不刷新心跳。
- **运动通路不加锁**（内部工单；审查 X3-01／08／11／14 所指的协议锁、等锁故障锁存与 `lock_faults` 字段一并退役）：协议核心分两半，串口侧 `yb_link` 归串口任务、控制侧 `yb_ctrl` 归控制任务，两侧不共享状态，只交换快照。
  - 指令槽（串口→控制）：单槽覆盖队列，装串口侧的最新指令快照——最近一条有效 `T:1` 的目标、到达时刻、序号，加心跳设置。控制环每拍零等待取一次。设置与运动同在一张快照里，后到的盖掉先到的也不丢设置。
  - 遥测槽（控制→串口）：单槽覆盖队列，控制环每拍写一张状态快照（测得轮速、电压、锁存、是否静默）。串口任务回反馈帧、判非零 `T:1` 收不收时零等待看一眼，不取走；快照可以旧一拍，控制侧收指令时按当拍的锁存再判一次。
  - 电压槽（传感器→控制）：每 200 ms 一次采样，去抖与锁存在控制侧。
  - 停车序号（审查 X3-15；原刹车标志）：32 位原子量，0 表示没有待办的停车。串口任务收到零速 `T:1` 即写入这条零速的序号，再投指令槽；控制环每拍取走并清零，取到即本拍按零目标刹停。取到时控制侧已收下的快照若早于这条停车（零速的快照还没到），一并清掉目标并记下序号，此后早于它的快照不取，等到这条零速或更晚的指令才恢复；已收下的快照不早于它时只刹这一拍。
- **三条不变量**（宿主侧用例在 `tests/real/test_yb_eet01_proto.py`；任务调度未上板验证）：
  1. 零速或 STOP 到达后一个控制周期内必生效。「到达」指串口任务收完这一行；本固件的 STOP 就是零速 `T:1`。每条零速指令至少换来一拍刹车，同一拍里后面又到了非零指令也先刹这一拍，非零指令下一拍生效。
  2. 任何指令不因另一任务而丢失或延后。串口任务收完一行当即处理、当即回包。同一拍之内连到几条 `T:1`，以最后一条为准，前面的算被上位机自己的后一条指令取代，不算丢。
  3. 串口任务永不等待控制任务，反之亦然。`main.c` 里没有互斥锁与信号量，队列的收、看一律零等待，写一律覆盖。轮速、姿态两处各有一个自旋临界区：轮速一处（`drive.c`）进出都只拷数；姿态一处读出（`sensors_get`）只拷数，写入（`sensors.c:125–130`）却是在临界区内算两次 `atan2f`、一次 `sqrtf`，不是只拷数（审查第四轮点出）。把这几步算术移出临界区排在门一之后（内部工单），现在的代码未改。
- **后备刹车**（修订5 R2；审查 X3-11）：任务看门狗只监视控制任务，`timeout_ms` 300（`YB_CTRL_WDT_MS`），控制环每拍喂一次；控制任务停摆 300 ms 即 panic，panic 不打印、立即复位。`ESP_ERROR_CHECK` 失败同样走 panic 复位。从停摆到复位这段时间 PWM 保持最后的占空比；复位期间电机管脚的电平与 H 桥的状态（刹还是滑）**未上板验证**，门二「复位即停」一项核。
- **开机静默与复位锁存**（修订5 R2）：开机即在复位锁存里，任何复位后 2 s 内不出力。静默期内零速 `T:1` 照收，非零 `T:1` 回 `{"T":-1,"err":"boot_quiet","got":1}`；静默满 2 s 之后复位锁存仍在，下一条有效 `T:1` 才清除，车不会自己动起来。开机即采一次电压，低压去抖自开机起算：复位清掉的低压锁存，电压仍低则在静默期内重新锁上；采样晚到、去抖段还没落定时，静默顺延到它锁存或回升为止。
- **复位原因与 boot 计数**（修订5 R2）：反馈帧的 `reset_reason` 是 ESP-IDF 5.1 `esp_reset_reason()` 的原值（1 上电或 RESET 键、3 软件复位、4 panic、5 中断看门狗、6 任务看门狗、9 欠压；各种复位实际报哪个值未上板验证）。`boot` 放在复位不清的 RTC 区，带魔数与 CRC（内部工单-2，`components/proto/yb_boot.c`）：开机时校验过就加一，校验不过（上电、RESET 键清了 RTC 区、首刷）才取随机起点；不看复位原因，不为 0。看门狗复位链上逐次加一、可计次；RTC 区跨 RESET 键保留就照常加一，不保留就换新起点，两种都不撞号（随机起点撞上旧值的概率约 2^-30）。随机种子在开机时临时打开内部熵源取一次（`bootloader_random_enable`），因为应用起来之后没开 RF 时 `esp_random()` 只是伪随机，RESET 清了 RTC 区的话可能次次相同；熵源占 SAR ADC，在开 ADC 之前关掉。它不是从 1 数起的次数。RTC 区在各种复位下保不保留未上板验证，门一A 两种结果都过一遍。上位机只看它在回合内变没变，变了即急停并作废（`void_reason="reset"`）。运行期不写闪存。
- **零目标按轮刹车**（审查 X3-02）：哪一侧目标为零，就刹那一侧的两路并清它们的 PID 状态，不等两侧同时为零。控制律在 `components/proto/yb_wheel.c`，宿主侧可测。
- **低压锁存**（裁定 2026-09-28-08）：阈值＝每芯 3.25 V × 芯数，2S 电池包即 6.5 V；每 200 ms 采一次，连续 2 秒低于阈值即锁存。**软件清不掉**：没有任何指令能解除，电压回升也不解除，只有断电或点 RESET 重启才清。锁存后零速 `T:1` 照收，非零 `T:1` 回 `{"T":-1,"err":"low_voltage","got":1}`，反馈帧的 `low_voltage` 为 1。不设预警级。`YB_LOW_VOLT_PROTECT=0` 关闭。
- **只插 USB 的安全态**（审定方核定，内部工单；2026-10-10 勘误，内部工单 §4）：仅 USB 时分压点读≈5 V（10-10 三次），该节点亦受 USB 轨到达；原「≈0」为设计假定。开机 2 秒后即进低压锁存，轮子转不了。这是安全态，不是故障。上电顺序＝先开电池再插 USB；先插了 USB 就在开电池之后点一下 RESET。低压锁存只由芯片复位清，RESET 键与断电重启都算。
- **电压校准**：首通电拿万用表比对反馈帧的 `v`，偏差超过 0.15 V 就改 `YB_BAT_CAL`（＝万用表读数÷板读数）。
- **蜂鸣器**：心跳锁存与低压锁存触发时各鸣一声（200 ms）；复位锁存不鸣。心跳锁存在两拍之间被 `T:1` 清掉的话会漏鸣。`YB_BEEP_ENABLE=0` 关闭。
- **急停的锁存与清除在上位机**（`real/ugv02.py` 的 `emergency_stop`／`clear_estop`）。固件没有专用急停指令；上位机发零速，固件心跳锁存兜底。上位机的清除入口解不了固件的低压锁存。
- **停车确认**（审查 X3-08，内部工单）：发出零速不等于车已停。上位机急停后读反馈，一帧同时满足 `tl`＝`tr`＝0 且 `L`、`R` 低于停稳阈值才算确认（`stop_confirmed`）；确认不了就再发一次零速再问，至多 `stop_confirm_tries`（缺省 3）次，到数记 `stop_confirmed=False`、锁存不变。回合动作结束的停稳核验同样看 `tl`、`tr`。零速那一行在串口上丢了（缓冲溢出、线噪）的情形由此被读出来，不再静默。UGV02 固件没有 `tl`、`tr`，只看轮速。
- **上位机一侧**：驱动层读到针对运动指令的错帧会抛类型化异常（`BadArgsError`／`LowVoltageError`／`UnknownCommandError`，都是 `SafetyError` 的子类）并锁存急停；`real_env` 收到低压即把该回合标作废；配置了 `min_start_voltage_v`（旧车预设 7.0 V）时，电压不够不开回合。
- 上电先把四路电机置于刹停，再开串口。

## 自检钩子（只在台架用；内部治理仓 内部工单）

任务看门狗复位在台架上造不出来，生产固件没有让控制任务停摆的入口。自检固件多一个编译门控的模块 `main/selftest.c`，让控制任务按四种方式停摆，用来实测复位报什么原因、多久复位、电机多久停。

- **门控**：构建开关 `YB_SELFTEST` 缺省关。关着时 `selftest.c` 不进编译，`main.c` 里两处调用是空函数，镜像里没有钩子命令名（`tests/real` 有一条用例对 `build/yb-eet01-json.bin` 跑 `strings` 核）。开关只许开在单独的构建目录 `build-selftest/`，换别的目录名配置阶段即报错，所以 `build/` 出不了自检固件。
- **版本**：自检固件的标识行是 `"ver":"0.2.0-selftest"`。上位机 `real.smoke` 见这个后缀即拒跑；驱动层读到带后缀的标识行，该回合作废（`void_reason="selftest_firmware"`）。自检固件不进任何回合数据，用完刷回生产版，刷回后读标识行核版本。
- **四条钩子命令**，只做停摆，除此没有别的调试入口。指令号在 UGV02 指令集之外（上游 `json_cmd.h` 全表最大 1041），须整行逐字节相符；生产固件收到只回 `unknown_cmd` 错帧。

| 命令 | 停摆方式 | 文档推得的复位原因（未上板验证） |
|---|---|---|
| `{"T":9101,"hook":"yb_stall_block"}` | 阻塞：永久等待 | 6 任务看门狗 |
| `{"T":9102,"hook":"yb_stall_spin"}` | 空转，中断开 | 6 任务看门狗 |
| `{"T":9103,"hook":"yb_stall_spin_noirq"}` | 空转，中断关 | 5 中断看门狗或 6 任务看门狗：两者超时都是 300 ms，谁先到未核实 |
| `{"T":9104,"hook":"yb_stall_abort"}` | `abort()` | 4 panic |

- 停摆发生在控制任务里、当拍喂狗之后，PWM 停在上一拍的占空比。串口任务登记钩子后这一行不交给协议核心，不回包。
- **按复位类判，不按单值**：类＝上电或外部（1、2）、软件（3）、异常（4、5、6、7，即各看门狗与 panic）、掉电（9）。上位机的判据只用类（`real/ugv02.py` 的 `reset_class`），单值只进日志与冲刺卡的表。固件自己不按复位原因分支，boot 计数只看 RTC 区校验。
- **上位机入口**：`python -m real.stallcheck --port <串口> --firmware-ver 0.2.0-selftest --kind block|spin|spin_noirq|abort`，轮子离地。它先以 0.05 m/s 转 2 秒，发钩子命令，记从发出到标识行到达的时长，再读回复位原因与 `boot`，并盯轮速到 2 秒之后。触发后 2 秒轮子仍转即台架红牌。结果记在 `smoke_runs/<日期>-selftest/stall.csv`，与生产版的 runs 目录不混。

## 配置

全部在 `main/yb_config.h`，可用编译选项 `-D名字=值` 覆盖。管脚逐脚见 `docs/pins.md`，取自厂商《microROS控制板简介.md》的 GPIO 管脚分配表，不自拟；PWM 走乐鑫 `bdc_motor` 组件（MCPWM，25 kHz），资源分配同厂商例程。

| 项 | 缺省 | 状态 |
|---|---|---|
| 轮径 `YB_WHEEL_DIAMETER_M` | 0.065 m | 65 mm 尼龙麦轮的标称外径（商品页 Φ65，主理人 09-28 供图）。门二标定后改成实测值 |
| 轴距 `YB_WHEEL_BASE_M` | 0.119 m | 同侧前后轮心距，主理人 09-28 照片上的卷尺读数，±3 mm |
| 轮距 `YB_TRACK_WIDTH_M` | 0.1486 m | **10-02 实量**（B0 步 5）：同轴左右轮外端面距两读 178／180 mm，均值 179 减轮宽 30.4。此前估算 0.142 ±5 mm（审定方俯视照片轮心距法复核 0.139／0.144），实量高出 6.6 mm |
| 转向等效宽度 `YB_TURN_WIDTH_M` | 0.2676 m | 轴距＋轮距。麦轮按差速跑时左右轮速差与车体转速的换算用它，不用几何轮距。门二实测转角后校 |
| 每圈计数 | 1040 | 厂商《310电机参数》：13 线 × 1:20 × 4 倍频 |
| 轮位 | Motor1 左前、Motor2 左后、Motor3 右前、Motor4 右后 | 待门一核对 |
| 电机与编码器方向 | 同厂商例程（左侧两路 PWM 的 AB 脚对调，右侧两路编码器的 AB 相对调） | 待门一核对；`YB_MOTOR_SIGNS`、`YB_ENC_SIGNS` 逐路取反 |
| 固件限幅 `YB_MAX_WHEEL_MPS` | 0.5 m/s | 上位机动作实际发出的轮速：前进 0.20 m/s，原地转约 0.14 m/s（按转向等效宽度 0.2676 m）；驱动层校验上限约 0.34 m/s |
| PID | 增量式，Kp 1.0、Ki 0.2、Kd 0.2，输出限幅 ±200（PWM 计数），另加死区 200 | 厂商例程值，待门二标定 |
| 电池分压系数 | 4.03 | 厂商例程值 |
| 低压阈值 | 6.5 V | `YB_BAT_CELLS`（缺省 2）× 3.25 V。芯数 10-01 看电池标签核 |
| 电压校准系数 `YB_BAT_CAL` | 1.0 | 首通电比对万用表后定 |

上位机 `UGV02Config` 的 `wheel_diameter_m`、`pulses_per_revolution`、`track_width_m` 缺省是 UGV02 的值；接旧车时 `track_width_m` 要填**转向等效宽度**（现值 0.2676 m），它决定转向角的换算。填几何轮距 0.1486 m 的话，车实际转过的角度只有预期的一半多一点。轴距、轮距、转向等效宽度三个量固件的四条指令都用不到。

## 编译

需要 ESP-IDF v5.1.2，首次编译联网取 `espressif/bdc_motor` 0.1.0。

```bash
export PATH=/usr/bin:$PATH && . ~/esp/esp-idf-v5.1.2/export.sh
cd real/firmware/yb-eet01-json && idf.py build
```

`sdkconfig` 由 `sdkconfig.defaults` 生成，不入仓。烧录带 `-b 115200`：`idf.py -p <串口> -b 115200 flash`（10-02 实机 460800 三次 `Invalid head of packet`，裁定 2026-10-02-21；esptool 速率，与固件 `YB_UART_BAUD` 无关）。

自检固件另编在 `build-selftest/`，不动 `build/`；烧录也要带 `-B build-selftest`：

```bash
idf.py -B build-selftest -D YB_SELFTEST=1 build
```

## 宿主侧自检（不接板）

```bash
pytest tests/real/test_yb_eet01_proto.py -q
```
