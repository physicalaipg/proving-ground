# YB-EET01 整片备份与回退规程

> 内部工单 P3。编写：维护者，2026-09-28。**脚本只做过不接板的自测，规程未经实机执行。** 执行日 10-01。
> 硬规则：**备份不成立，不烧录，本路线停。** 任何一步出现预期以外的情况，停下，把屏幕原样贴回，不猜修。

## 这份规程保什么

板上出厂固件不开源，板上现在是哪一版也不知道。先把整片 Flash（4 MB）读出来存好，往后任何时候都能原样写回。备份里可能带 WiFi 名与口令，所以只存本机 `~/esp/backups/yb-eet01/`，不进任何仓库、不外传。

## 进条件

- 台架，四轮离地；电池电压已量（7.4～8.4 V）；物理断电开关够得到。
- Type-C **数据线**一端接板上标「Type-C 串口」的口，一端接 Mac。板上另一个 Type-C 口是给树莓派供电的，不接。
- 本机已装 esptool：`~/esp/esptool-venv/bin/esptool.py version` 末行是版本号。
- 速率 115200（脚本缺省；10-02 实机 460800 不通，见「回退」节末）。

## 步骤

| 步 | 谁 | 做什么 | 预期 | 其他 |
|---|---|---|---|---|
| 1 | 主理人 | 插 Type-C 数据线，打开板上电源开关 | 电源指示灯亮 | 停下贴回 |
| 2 | 维护者 | `ls /dev/cu.usbserial-* /dev/cu.SLAB_USBtoUART*` | 列出一个设备，记作 `<串口>` | 换一根数据线再试一次；仍无设备，停下贴回 |
| 3 | 维护者 | `bash tools/yb_backup.sh backup <串口>` | 见下「预期输出」 | 见下「三分支」 |
| 4 | 维护者 | 读开机版本行：`bash tools/yb_backup.sh bootlog <串口>`，脚本复位一次并读 5 秒；没有文字出来就重跑，由主理人在 5 秒内点一下 RESET | 能读的启动文字，其中有含版本号的行 | 无输出或乱码：停下贴回，不换波特率乱试 |
| 5 | 维护者 | 把备份目录路径、哈希、判定结果、版本行写进回执 | — | — |


### 连接方式：先自动，后手动

脚本先试自动复位：esptool 经 CP2102 的 DTR、RTS 两根线把芯片拉进下载模式。连不上时脚本会停下提示，改走手动下载模式：

1. 按住板上 **BOOT** 键不放；
2. 点一下 **RESET** 键；
3. 松开 BOOT 键；
4. 在脚本提示处按回车。维护者在非交互环境里跑时，改用 `YB_MANUAL=1 bash tools/yb_backup.sh backup <串口>` 重跑。

手动模式下读完不会自动重启，点一下 RESET 回到正常运行。

### 三分支

- ✅ 末行 `✔ 备份成立` → 备份日过，进门一。版本判不出（`版本未判定`）不影响备份成立，照实记。
- ⚠ 连不上板（退出码 3）→ 按上面走一次手动下载模式；仍连不上，停下贴回。
- ❌ 两次读出不一致、读出长度不等于 Flash 容量、落盘失败（退出码 4）或镜像头异常（退出码 5）→ **备份不成立，不烧录，当日停**，贴回。镜像头异常的可能原因是空片、Flash 已加密或读错，都要审定方定。

备份成立时目录里有三个文件要一起留着：`backup.bin`、`backup.bin.sha256`、`backup.bin.id`（芯片型号、MAC、Flash 字节数、镜像 sha256）。回退时三个都要在，而且须出自同一次备份。

## 回退

```bash
bash tools/yb_backup.sh restore <串口> ~/esp/backups/yb-eet01/<时间戳>/backup.bin
```

脚本依次核五件事，任一不过即拒写（退出码 6）：镜像哈希与备份时所记一致；镜像长度等于备份时所记的 Flash 容量；板身份文件里绑的镜像哈希就是这份镜像的（旁文件混配即拒）；输入 `RESTORE` 确认；目标板的芯片型号、MAC、Flash 容量与备份时所记逐项相同。都过了才从 0x0 整片写回，写回命令的 `--flash_mode`、`--flash_freq`、`--flash_size` 三项全 `keep`，闪存参数保持镜像头原值，不让 esptool 改写引导头造成读回哈希假不一致（内部工单 C4）。写完自动复位，开串口看启动文字核对版本行。

**速率**（内部工单 A2，裁定 2026-10-02-21）：备份、回退、烧录的 esptool 速率一律 115200，脚本缺省即此；460800 只许 `YB_BAUD=460800` 显式给，门日不试其他速率。证据：10-02 本板 460800 切速后首条命令三次 `Invalid head of packet`（含手动下载模式、换线换口），115200 两次读出哈希一致。此处只指 esptool 速率，固件运行时串口协议波特率（`YB_UART_BAUD`）不动。

只回退本脚本备份出来的镜像，而且只写回原来那块板。换板或拿别处来的镜像，脚本不写。

回退写回的是整片，WiFi 与代理地址等配置随备份一起回来，不用重配。只有拿厂商镜像（入箱件 `firmware-factory/`）回刷时才要用厂商的配置脚本重配，那份脚本没有入仓，在源路径。

## 出条件

备份成立、哈希入回执、板上固件版本判定结果入回执、开机版本行入回执。

## 脚本自测（不接板）

```bash
bash tools/yb_backup.sh --self-test           # 末行「结果：10 过 / 0 失败」
```

前四条判版本与哈希；后六条用假 esptool 走备份与回退的整条通路（UTF-8 环境下备份走完、截短的读出被拒、同板可回退、换板被拒、长度不足的镜像被拒、旁文件混配被拒），不碰任何设备。脚本不抵御有人把三个文件一起改掉。
